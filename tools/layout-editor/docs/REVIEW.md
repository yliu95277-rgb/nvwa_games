# 编辑器独立 QA 审查

本次依据 app.mjs、layout-core.mjs、serve.mjs、适配文档与 editor-desktop.png 审阅，并独立运行 `node tools/test-layout.mjs`，结果通过。未在本次独立审查中重新运行完整浏览器脚本或 Cocos 重编译；其结论应参考最终执行记录。

## 判断

该实现满足初始可复用 2D 图形布局编辑器的核心范围：单选对象、移动/缩放/旋转、检查器、图片导入、层级、隐藏/锁定、复制/删除、事务撤销重做、JSON 往返和浏览器持久化。数据核心与 DOM、Cocos 桥分离，独立静态 dist 可部署。它不是 Cocos 的实时远程编辑器，也不是任意场景/Prefab 编辑器。

1280×800 截图中三栏布局可用，画布、选中框、工具与属性可辨认。大量属性会使检查器滚动，底部帮助卡片是固定辅助区域。主城节点目前按 ID 直接展示，命名偏开发者，但不阻止操作。

## 已确认

- 数据校验拒绝无效引用、父级循环和异常尺寸/缩放；未知字段不带入状态。
- 历史模型支持拖动事务合并、父子子树复制/删除；最多 100 个历史快照。
- 导出将图片嵌入 JSON，能解除主城资源路由依赖；远程图片仍受 fetch/CORS 约束。
- IndexedDB 已用于当前文档保存，旧 localStorage 文档只作加载回退；README/PORTABILITY 已同步修正。
- 本机服务固定根目录与写回目标，限制 Host/Origin；静态部署无这些 Cocos API。

## 需要父代理确认/处理的适配一致性

1. 主城写回接受已支持 Sprite ID 的子集。编辑器删除节点后，如果 LayoutBridge 只是遍历存在的布局节点，原游戏节点仍会显示，与编辑器不一致。应通过桥隐藏缺失节点、拒绝不完整集合，或明确将删除转换为 visible=false。此项属于真实编辑结果一致性问题，需回归。
2. schema 的 z 接受有限小数，但浏览器渲染使用 Math.round(n.z)。小数 z 的相对顺序可能因舍入改变，且与另一个引擎按原值排序不同。应统一整数约束或统一渲染排序解释。

## 交付时应保留的限制

- 单选；无多选/对齐分布/完整文本样式面板。文字节点可经 JSON 创建，不必为首版增加按钮。
- 父节点改变重新解释局部坐标，不保持世界位置；z 只在同父级空间内有意义。
- 主城只接入既有根级 Sprite ID，不能把任意新图像、父子层级或脚本直接写进 Cocos 场景。
- 保存浏览器文档不等于写回游戏；写回后必须重编译。
- 无效主城适配、静态站点缺少主城 API、图片导出失败应显示错误，不能宣称成功。
- 未进行公网托管；本机接口不应原样用作公网账户/权限后端。

## 建议最终验收

用一次实际拖动、旋转、改锚点、撤销/重做、隐藏、复制/删除、保存刷新和嵌图导出导入检查编辑器；另用合法主城节点移动/隐藏写回并重新构建，截图确认游戏位置和输入跟随。完整静态 dist 另起服务导入嵌图 JSON，确认没有 /project-assets 依赖。上述适配删除与 z 一致性处理后再标记内部审核通过。

## 最终处理结果

上述缺失节点删除语义已通过桥隐藏节点及其HUD关联对象，并用实际Cocos构建/运行验证。小数z改为同父节点排序后映射CSS层级，不再四舍五入。浏览器与引擎链路均通过，详见 cocos-roundtrip.json。
