# Q 版三国主城实现与验收规格

本文是实现目标与验收依据，不代表功能已经完成。视觉依据为同目录 `reference.png`。实际完成状态以交付报告、运行截图和测试结果为准。

## 视觉目标

采用横屏 16:9、等距俯视、Q 版建筑和人物。主城府是中心视觉焦点；招贤馆在左上，兵营在右侧，集市与铁匠铺在左下；城门位于下方中央。保留暖色阳光、红金 UI、灰蓝屋顶、绿色植被和远处敌城。顶部资源、右侧工具、底部导航与右下出征形成固定操作框架。

设计尺寸统一使用 1672 × 941 参考画布坐标，运行时按实际窗口等比缩放并做安全区适配；实现可选择等比例标准分辨率，但应记录换算关系。不可通过非等比拉伸追求满屏。建筑热区与背景共享同一坐标变换，避免宽高变化后点击错位。

## 图层设计（从后向前）

| 层 | 内容 | 复用与交互约束 |
|---|---|---|
| 0 背景 | 天空、山体、远景敌城 | 装饰，不阻挡输入；首版可合并为底图 |
| 1 地形 | 地面、河流、道路、植被、静态阴影 | 为建筑和角色预留遮挡补全，不含动态文字 |
| 2 建筑 | 城主府、招贤馆、兵营、铁匠铺、集市、城门 | 按建筑配置生成；底部中心锚点；独立点击热区 |
| 3 角色与装饰 | 武将、士兵、旗帜、火焰与生产反馈 | 按脚底位置排序；动画独立于逻辑状态 |
| 4 场景标签 | 建筑名、等级、可领取提示 | 代码文字；缩放与点击目标尺寸独立控制 |
| 5 HUD | 头像、等级、资源条、右侧工具、底部导航、出征 | 固定屏幕安全区；不随场景位置排序 |
| 6 弹窗 | 建筑详情、招募、升级、背包、任务 | 单一遮罩和焦点栈；关闭后恢复主城输入 |
| 7 战斗 | 战场、单位、弹道、战斗 HUD、结算 | 独立页面或根节点；主城状态由共享数据服务保存 |
| 8 系统反馈 | Toast、错误提示、加载状态 | 不重复叠加；避免永久阻断点击 |

如果首版使用完整参考图作为静态底图，必须明确它是合成图：其中建筑、人物和 UI 仍是烘焙像素，不能描述为已经完整拆层。需要覆盖或重绘的动态数字、文案与状态应另做独立组件，且不能留下原图重复文字。视觉忠实与资产独立性分别验收。

## 可复用组件边界

| 组件/服务 | 输入配置 | 责任 |
|---|---|---|
| ResourceBar | 资源类型、图标、余额、格式、可选加号操作 | 展示与刷新资源；不自行决定扣费规则 |
| BuildingHotspot | 建筑 ID、位置、热区、名称、等级 | 可视反馈、点击派发；兼容未来更换建筑图 |
| BuildingPanel | 建筑配置、等级、收益/成本、操作回调 | 统一详情、升级、领取和禁用原因 |
| NavigationBar / NavItem | 页面 ID、图标、标签、红点、当前项 | 选择状态和切页；避免每个按钮复制逻辑 |
| ModalHost / ModalPanel | 内容、标题、关闭行为 | 遮罩、互斥输入、层级和返回键行为 |
| GeneralCard | 武将 ID、头像、稀有度、等级、状态 | 招募、武将列表、布阵复用相同展示 |
| CampaignBattle | 关卡配置、已选武将、进入/退出回调 | 战斗生命周期、波次、部署和结果 |
| EconomyService | 资源账本与建筑配置 | 单次原子扣费/发奖；拒绝负数余额 |
| SaveService | 存档版本、状态快照 | 本地持久化、默认值、损坏数据恢复和迁移 |

场景节点只持有表现状态；经济和存档逻辑独立于按钮和弹窗，便于新增建筑或更换美术。所有建筑、关卡、升级曲线和奖励采用配置数据，以 ID 关联，禁止依靠显示名称查找逻辑。

## 资产清单与来源

资产清单应记录 ID、路径、用途、画布尺寸、锚点、透明度、层级、来源、生成/编辑记录与验收状态。参考图属于风格与构图来源，不应冒充可编辑原稿。

最小资产分组：主城底图/地形；五栋功能建筑与城门；角色头像和可复用单位；资源/导航/功能图标；按钮与弹窗底板；战场、敌兵、塔/武将与弹道。能以代码完成的文字、数字、红点、血条和进度条不烘焙到素材中。重复使用资产保持相同视角、描边、光照方向和透明边缘；独立建筑必须补齐被遮挡区域。每个进入运行包的资产应能在清单中追溯。

## 可玩的最小闭环

1. 首次进入主城显示初始资源和建筑状态。点击建筑可打开详情；升级产生实际扣费、等级和收益变化，余额不足有明确反馈。
2. 招贤馆可招募或选择武将；武将页展示结果；布阵页至少能选择进入战斗的单位。
3. 出征进入独立塔防关卡。至少包含可辨认路线、多个部署位置、两类可部署防御单位/武将、多波敌人、金币消耗、击杀奖励、基地生命与胜负条件。
4. 玩家可以部署和升级防御、观察敌人沿路径前进与受击、获得胜利或失败结算。暂停期间模拟停止；重试清空旧战斗实体；返回主城恢复 HUD 与输入。
5. 战斗胜利奖励只领取一次。资源、建筑等级和武将状态经本地存档后，刷新或重启仍保留；战斗中途退出不得重复刷结算奖励。
6. 至少验证首次进入、正常胜利、失败/重试、资源不足、重复点击、重新加载和窄窗口安全区。确定性随机种子或测试关卡可用于复现。

本地经济是单机演示状态，不承诺联网账户、防作弊或商业支付。离线收益如实现，应限制计时上界并处理系统时间回拨；如未实现，应在交付说明中明确。

## 编译与运行验收

记录 Creator 精确版本、构建目标、完整构建命令/配置与退出结果；可玩构建应有明确启动方式。必须在真实输出中检查交互与控制台，编辑器预览和 TypeScript 语法检查不能替代最终构建。失败或无法执行的检查原样报告，不用“代码完成”代替“编译通过”。

## 与参考图的差异验证

保存三类证据：原始参考图；相同宽高比、主城默认无弹窗状态的运行截图；标注差异的对照图。保存截图尺寸、构建版本/提交 ID、资源状态和截图步骤，避免状态不同造成误判。

先按归一化坐标比较城主府、招贤馆、兵营、集市、铁匠铺和城门的中心及边界；再比较顶部资源区、右侧工具区、底部导航和出征按钮。列出每项“保留/改动/缺失/待验证”，说明改动原因。

重点人工检查：构图比例与视觉层级；建筑视角/画风；字重与可读性；UI 是否遮挡主建筑；按钮是否可点击且反馈与视觉一致；不同窗口下是否出现拉伸、裁切或热区偏移。可提供半透明叠加与滑动对照，但像素差异只能辅助定位，不能证明美术质量或玩法正确。

最终交付应同时给出：可玩构建、源码与本地 Git 历史、资产清单、层级/组件说明、测试记录、对照证据和已知差异。审核者以实际运行结果确认完成项。
