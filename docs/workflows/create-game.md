# 新建游戏

1. 在 games/<game-id> 创建匹配引擎版本的工程，保留项目自己的启动、构建与README。游戏的所有运行资源与数据放在游戏目录。
2. 从 packages 中选择需要的维护模块，显式复制运行源码到游戏内，记录 framework-lock.json 的版本、源位置和SHA256。不要引入指向根仓库的运行时import。
3. 在 projects/<game-id>.json 描述路径、引擎、布局与资源映射、画布和命令。当前根game命令固定主城配置；新配置不会自动改变默认命令，需显式接入。
4. 编写受限编辑器适配器，明确支持的节点ID、层级、资源与写回目标。没有适配时先通过可移植JSON交换，不伪造写回成功。
5. 复用技能工作流，保留资产来源与尺寸/锚点说明。玩法代码和可复用组件应能在游戏内独立运行。
6. 运行相关测试；复制完整游戏到仓库外或artifacts独立目录，完成匹配引擎构建与真实试玩。停止根工具服务确认无隐式依赖。

新游戏应是新的独立交付边界；共享维护源的便利不能取代其自己的构建说明和验证证据。
