# 构建与交付游戏

1. 确认工作树、项目配置与引擎精确版本；记录待交付提交。需要公共模块更新时先显式同步并更新哈希锁，不在发布过程中自动追随最新维护源。
2. 完成模型与浏览器交互测试，确认布局、资源和点击热区一致；如编辑器写回过布局，重新构建游戏。
3. 执行独立性扫描与复制（主城：node scripts/verify-game-standalone.mjs）。复制范围应包含运行源码、资源、settings、构建配置、本地桥与README，不包含library/temp/.git等缓存。
4. 在独立复制目录使用匹配Creator执行构建。源码静态扫描或复制成功不等于编译成功；记录真实构建退出结果和日志。
5. 用HTTP服务启动最终Web输出，关闭编辑器本地API再试玩，检查资源加载、存档、胜负、返回主城和布局热区。留存版本、视口与截图对照。
6. 整理源码、可玩输出、操作说明、图层/组件边界、已知限制、测试摘要与许可来源。压缩包中使用相对路径；不含开发机密钥和根工具绝对路径依赖。
7. 本地Git提交维护源码与必要说明；用户明确请求前不推送或公开托管。服务器发布需要独立配置，不把开发机写回接口原样暴露公网。
